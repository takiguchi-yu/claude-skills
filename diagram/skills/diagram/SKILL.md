# 図を描く

## 出し先ごとの形

| 出し先 | 載せるもの |
| --- | --- |
| 応答 | `mmd2txt` の出力 |
| GitHub で読む Markdown | ` ```mermaid ` の元記述 |
| Jira・Confluence・Slack | `mmd2txt` の出力 |

GitHub で読む Markdown は Mermaid をそのまま書けば図になるので、下の変換と確認は要らない。番号の振り方と本文との対応は、出し先によらず同じ。

## 図は mmd2txt で描く

Mermaid で書き、`mmd2txt` で罫線の図に変換して、出力をそのままコードブロックに載せる。
罫線の箱はすべて道具に描かせる。日本語と罫線の表示幅は、道具が数える。

```sh
mmd2txt <<'EOF'
graph LR
  A["[1] 利用者"] --> B["[2] API ゲートウェイ"]
  B -->|[3] 照会| C["[4] 注文サービス"]
EOF
```

- 横向きの `graph LR` から始める
- `mmd2txt` は中で mermaid-ascii を呼ぶ。対応するのは `graph` と `sequenceDiagram`（`erDiagram` は記号が崩れ、`stateDiagram` と `classDiagram` は未対応）
- 状態遷移と実体の関連は `graph` で描き、状態は遷移の契機を、実体は多重度（`1:N` など）を矢印のラベルに書く
- 道具を通さずに手で書く小さな図は、`[1] 利用者 --> [2] API --> [3] DB` のように 1 行に並べ、枠の箱を作らない

## 載せる前に出力を確かめる

mermaid-ascii は配置を誤ることがあり、エラーにならずに崩れた図を返す。出力を読み、次の 7 点を満たしてから載せる。

- ラベルがすべて欠けずに出ている（線がラベルの文字に食い込んでいない）
- どの矢印にも、行き先に矢印の先（`►◄▲▼`）がある。同じ行き先へ合流する矢印は、1 つの先を共有してよい
- 1 本の線に、出発点も行き先も違う矢印や、逆向きの矢印が乗っていない（乗ると、ラベルがどの矢印のものか読めない）。同じ出発点から分かれる線と、同じ行き先へ合流する線は共有してよい
- 線どうしが交差していない（グループの枠をまたぐ所以外に `┼` が出ていない）。`graph TD` で 1 つのノードから 3 本以上に分かれると交差する
- グループ（`subgraph`）の枠の中にあるのは、その `subgraph` で定義したノードだけ
- シーケンス図のメッセージが、途中の役者の縦線を隠していない。隠すなら、メッセージを番号と 2〜4 字に縮め、詳しくは本文の同じ番号の段落に書く
- 横幅が **100 桁以内**（超えると `mmd2txt` が標準エラーに警告を出す）

満たさなければ、上から順に試す。1 つ試すたびに 7 点を確かめ直す。

1. `graph LR` と `graph TD` を入れ替える
2. `subgraph` を外す
3. 経路ごとに図を分ける（例: リクエストの経路と非同期処理）。3 本以上に分かれる部分と、往復する 2 つのノード（A→B と B→A）は、その部分だけを `graph LR` の図に切り出す。分けた図どうしで、同じノードには同じ番号を使う
4. 分けると意味が失われる図に限り、その旨を本文に 1 文書いてから、Artifact に Mermaid を載せて描く
