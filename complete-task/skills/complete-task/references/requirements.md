# 元の要件との対応

`complete-task` スキルは次の 10 項の要件を実装したものである。`SKILL.md` の手順を変えるときは、対応する要件が空文化しないかをここで確かめる。

| 元の要件 | 実装箇所 |
|---|---|
| 1. まず現在のフォルダ・資料・環境を確認 | 手順 1 |
| 2. 調査・実行・レビュー・検証に分解 | 手順 4 |
| 3. 独立した仕事は並列で複数サブエージェントへ | 手順 5（調査）、手順 7-3（レビュー） |
| 4. 3 視点（正確性 / 利用者目線 / リスク・抜け漏れ）でレビュー | 手順 7-2 で規模とリスクに応じて 1〜3 視点を選ぶ。3 視点は上限。省いた視点はオーケストレーター自身が見る |
| 5. 問題発見時はすぐ質問せず、まず原因調査 | 手順 6-1 |
| 6. 解決できなければ異なる方法を最大 3 つ | 手順 6-2 |
| 7. 修正後は必ず再検証 | 手順 8（2 周目以降は差分レビュー。再検証そのものは省かない） |
| 8. 完了条件をすべて満たして完成 | 手順 9 |
| 9. 承認なしに実行しない操作 | 冒頭「承認なしに実行しない操作」 |
| 10. 実施内容・検証結果・変更ファイル・残課題・人間の判断が必要な事項をまとめる | 手順 10 |

## トークン消費を抑える仕掛け（要件 3・4・7 と両立させるための設計）

要件を削らずにコストを下げるため、次を各所に埋めてある。緩めるときは、どの要件が空文化するかを確かめる。

| 仕掛け | 場所 |
|---|---|
| サブエージェントごとのツール呼び出し予算と上限 | `~/.claude/agents/ct-*.md` の「ツール呼び出し予算」節 |
| サブエージェントの返答量の上限 | `~/.claude/agents/ct-*.md` の「出力量の上限」節 |
| 調査体数を論点数でスケール | 手順 5 |
| 差分を 1 回だけ取得してファイル共有（体ごとの重複読みを避ける） | 手順 7-1 |
| レビュー視点数を規模とリスクでスケール | 手順 7-2 |
| 2 周目以降は差分レビュー・差分検証 | 手順 8 |
| 詳細ログの全文貼り付けを禁止 | 手順 10 |
| `ct-researcher` / `ct-verifier` は sonnet、レビュー 3 体は inherit | 各 `ct-*.md` の frontmatter `model` |
